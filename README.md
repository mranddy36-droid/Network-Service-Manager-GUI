# Network Service Manager — версия на Python с GUI

Эта версия добавляет графический интерфейс к Network Service Manager v2.5.4.
Она рассчитана на Windows 10/11 и совместима с JSON-профилями и объектами,
которые использует `NetworkManager.ps1`.

## Функции исходной программы

Исходник (`NetworkManager.ps1`) управляет физическими сетевыми адаптерами
Windows. Профили объединены в JSON-файлы объектов и имеют четыре режима:

- **Network** — VLAN и один постоянный IPv4 с маской и шлюзом;
- **MultiAddress** — несколько временных адресов IPv4 на одном адаптере;
- **Routes** — временные или постоянные IPv4-маршруты;
- **Mixed** — несколько адресов и маршруты вместе.

Также исходная программа умеет сохранять снимок исходной конфигурации,
возвращать DHCP и DNS, восстанавливать снимок, проверять связь через ping,
выполнять `PingTarget`, хранить настройки отображения `DeviceName`, темы,
вести журнал и определять VLAN-параметр драйвера.

## Запуск

1. Установите Python 3.10 или новее с `tkinter` (в стандартном установщике
   Windows компонент называется **Tcl/Tk and IDLE**).
2. Запустите `Start-Python.bat` или `NetworkManager.py`.
3. Для просмотра адаптеров права администратора обычно не требуются.
   Изменение VLAN, IP, маршрутов, DHCP и DNS требует запуска от имени
   администратора. Если операция завершится отказом доступа, закройте окно и
   откройте программу через **Запуск от имени администратора**.

Сторонние Python-пакеты не нужны. Сетевые операции выполняются PowerShell,
`netsh.exe`, `route.exe` и `ping.exe`, уже входящими в Windows.

## Работа с GUI

- Выберите физический адаптер в верхнем списке; кнопка **Обновить** перечитает
  адаптеры и их состояние.
- Выберите объект с профилями или создайте новый объект.
- Профиль создаётся через форму: выберите тип, заполните основные поля,
  затем при необходимости добавьте несколько IP-адресов или маршрутов.
  Ручное редактирование JSON не требуется. Категория помогает группировать
  профили, а `DeviceName` и `PingTarget` находятся в разделе «Дополнительно».
- Кнопка «Сохранить текущие настройки как профиль» считывает IPv4, VLAN,
  шлюз, DNS и маршруты выбранного адаптера, затем открывает форму нового
  профиля с заполненными значениями. DHCP-адрес можно сохранить как статический
  после предупреждения.
- Названия типов в интерфейсе переведены на обычный язык: «Один IP-адрес»,
  «Несколько IP-адресов», «Только маршруты» и «IP-адреса и маршруты».
  Под списком типа показывается объяснение, что именно изменит каждый вариант.
- Нажатие **Применить**, **DHCP / DNS** или **Восстановить исходное** сначала
  показывает подтверждение, поскольку эти операции меняют сетевую конфигурацию.
- Перед первой сетевой операцией создаётся `OriginalNetworkState.json`.
  Изменение файла объекта создаёт резервную копию `.json.bak`.
- Журнал операций находится в `Logs/BESKAR_YYYY-MM.log`.

Маску можно задать как `255.255.255.0` или `/24`. VLAN — число от 1 до 4094;
оставьте поле пустым, если VLAN не требуется. Для режима Mixed форма показывает
поля и адресов, и маршрутов.

## VLAN и безопасность

GUI распознаёт известные свойства ID (`VLAN_ID`, `RegVlanID`, `VlanID`,
`VLANID`, `*VlanID`). Свойство `Packet Priority & VLAN` не считается VLAN ID.
При сбросе VLAN используется только свойство `Optional` или
`DefaultRegistryValue` драйвера; если драйвер не сообщает безопасный способ
сброса, операция останавливается. Поддержка экзотических драйверов здесь пока
не столь полна, как исходный PowerShell-детектор.

Приложение не переключает адаптер автоматически и не удаляет APIPA-адреса.
Применение профилей может кратковременно прервать сетевое соединение. Режимы
`MultiAddress` и `Mixed` используют временное хранилище адресов, как исходник.
Добавленные маршруты удаляются системно вручную; GUI не предоставляет пока
отдельного экрана управления/удаления маршрутов.

## Данные

Пользовательские файлы создаются рядом с приложением:

```text
Profiles\<объект>.json
Profiles\<объект>.json.bak
OriginalNetworkState.json
PythonSettings.json
Logs\BESKAR_YYYY-MM.log
```

Исходный PowerShell-файл и документация остаются на месте. Python GUI —
отдельная реализация поверх Windows networking commands; исходный файл не
запускается как UI-бэкенд.
